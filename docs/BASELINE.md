## 2. Environment variables and secrets

| Variable | Used in | Notes |

| `EXPO_PUBLIC_SUPABASE_PUBLISHABLE_KEY` | `lib/supabase.ts` | Inlined into the JS bundle; acceptable only because it is a publishable key protected by RLS. A service-role key must never be used here. |

## 3. Code observations relevant to later phases

1. **Data access is coupled to the UI.** `App.tsx` calls `supabase.from('equipment')` directly. A repository interface is needed before adding a mock or an Amplify implementation.
2. **Tests do not exercise app code.** The validation predicate is duplicated inside the test file, so CI stays green even if `App.tsx` changes its validation.
3. **Navigation props are typed `any`.**
4. **`AGENTS.md` says to use Expo Router under `src/app/`**, but the app uses React Navigation. Plan: keep React Navigation; migrating is out of scope for the deadline.
5. `AGENTS.md` asks for `npx expo lint` before finishing, but ESLint is not configured.
6. `eas.json` relies on EAS cloud builds and remote versioning, which need an Expo account. The CI/CD plan instead builds locally on GitHub runners (`expo prebuild` + Gradle), so no Expo, Google Play or Apple account is required. `eas.json` is left untouched.
7. The Expo prebuild template signs `release` builds with the debug keystore. Acceptable for internal demo distribution only.

## 6. Proposed repository and branching structure

One repo, one app. Versions are **tags on one codebase**, not copied source trees, so V1 is preserved exactly and V1→V2 is a reviewable diff.

- Tag `v1.0.0` on `e064830` (current V1) and create frozen branch `release/v1` from it. Done first, before any refactor.
- `main` stays green; work lands through short-lived `feature/*` / `chore/*` branches and PRs.
- Version 2: `feature/v2-*` → PR → merge → tag `v2.0.0`; `version` 2.0.0 and `android.versionCode` bumped in `app.json`.
- Release workflow triggers on `v*` tags.

Target layout (additions only; existing files stay):

```
src/
  domain/equipment.ts        # Equipment type + isValidEquipment (tests import this)
  data/
    EquipmentRepository.ts   # interface
    supabaseRepository.ts    # wraps existing lib/supabase.ts, lazy client
    mockRepository.ts        # default when Supabase env is absent; CI needs no secrets
    index.ts                 # selects by EXPO_PUBLIC_DATA_SOURCE
scripts/publish/             # publishing adapter: mock now, Play/TestFlight later
.github/workflows/release.yml
aws/buildspec.yml            # CodeBuild comparison
.env.example                 # names only
docs/
```
